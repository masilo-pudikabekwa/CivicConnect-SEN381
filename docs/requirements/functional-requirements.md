# Functional Requirements (FRs)
Requirements are prioritised using MoSCoW (Must / Should / Could). Each requirement carries a unique ID, a traceable source, and testable acceptance criteria.

| ID | Requirement | Source | Priority | Acceptance Criteria |
|---|---|---|---|---|
| FR-01 | The system shall allow a citizen to submit a report describing a civic issue. | N01 / IN-01 | Must | Given a logged-in citizen on the report screen, when required fields are completed and submitted, then a new issue record is created with a unique reference number and status "Submitted". |
| FR-02 | The system shall require a minimum structured data set (category, description, location) for every submitted report. | N03 / IN-02 | Must | Given a citizen submitting a report, when a required field is missing, then submission is rejected and the missing field(s) are identified; when all required fields are present, the report is accepted. |
| FR-03 | The system shall confirm successful submission, including a unique reference number. | N02 / IN-07 | Must | Given a successfully submitted report, when submission completes, then a confirmation showing the reference number is displayed within 2 seconds. |
| FR-04 | The system shall allow a citizen to view the current status of a report they submitted. | N02 / IN-03 | Must | Given a citizen with a valid account or reference number, when they query status, then the current status (Submitted / Under Review / In Progress / Resolved) and last-updated date are shown. |
| FR-05 | The system shall allow authorised civic personnel to change a report's status to a valid next status. | N04 / IN-04 | Must | Given an authenticated civic-personnel user, when a valid status transition is selected, then the record is updated and timestamped; invalid transitions (e.g. Resolved to Submitted) are rejected. |
| FR-06 | The system shall allow civic personnel to filter and sort reported issues by category, status and submission date. | N04 / IN-04 | Should | Given a list of reports, when a filter/sort is applied, then the displayed list reflects the criteria within 3 seconds. |
| FR-07 | The system shall allow users to register an account and authenticate before submitting reports or accessing management functions. | N01 / N06 / IN-05 | Must | Given a new user, when valid registration details are supplied, an account is created; correct login credentials grant access; incorrect credentials are rejected with a generic error message. |
| FR-08 | The system shall restrict management and administrative functions based on assigned user role (Citizen / Civic Personnel / Administrator). | N06 / IN-05 / IN-06 | Must | Given a user without the Civic Personnel or Administrator role, when they attempt to access a management function, then access is denied. |
| FR-09 | The system shall allow an administrator to view accounts and activate, deactivate, or assign roles to them. | N06 / IN-06 | Should | Given an administrator, when a user's role or account status is changed, then the change takes effect on that user's next authenticated request. |
| FR-10 | Where a user has a registered email address, the system should notify them by email when their report's status changes. | N02 | Could | Given a report with a status change and a user with a stored email address, when the status changes, then an email is sent within 5 minutes. |
